# HolonicTrader

A live trading system for Kraken Futures, built around AEHML (Autonomous Entropy-Holonic Machine Learning): markets are read as regimes, agents carry explicit autonomy and integration parameters, and a governor decides when the system is allowed to act.

Personal research system. It trades a small account, and the results in this repository are not audited and should not be read as a track record.

## What is implemented

| Component | Where | What it does |
| --- | --- | --- |
| Holon core | `HolonicTrader/holon_core.py` | Base agent with `Disposition(autonomy, integration)`, shared context and proposal lifecycle |
| Entropy holon | `HolonicTrader/agent_entropy.py` | Shannon entropy over returns, regime classification ORDERED / CHAOTIC / TRANSITION, Rust fast path with scipy fallback |
| Governor and executor | `HolonicTrader/agent_governor.py`, `agent_executor.py` | Veto, sizing and order placement |
| Agent set | `HolonicTrader/agent_*.py` | Strategy, risk, diagnostic and perception holons (112 modules) |
| Rust engine | `rust_engine/` | 18 modules, ~3,700 lines: parallel walk-forward optimisation, ONNX inference, execution algorithms, trading loop |
| Walk-forward | `wfo_engine.py` | Out-of-sample evaluation harness |
| Models | `dqn_model.keras`, `xgboost_model.json` | Policy and signal models consumed by the agents |
| Tests | `tests/` | 94 test modules across engine, agents and pipeline behaviour |

Python 3.10+, Rust 1.70+ for the accelerator, Node 20 for the dashboard.

## Operating modes

Both modes are wired: execution rows recorded in this repository were written by the live path. Paper mode is available before capital is committed, and the governor can halt trading on entropy or risk conditions.

## Configuration

Credentials come from the environment and are never committed:

```
KRAKEN_FUTURES_API_KEY
KRAKEN_FUTURES_PRIVATE_KEY
KRAKEN_API_KEY
KRAKEN_API_SECRET
```

## Run

```bash
pip install -r requirements.txt
python -m pytest tests -q          # engine and agent tests
python main_live_phase4.py         # live loop (requires credentials)
python wfo_engine.py               # walk-forward evaluation
```

The dashboard is a separate Node application (`package.json`, `web_dashboard.py`, `dashboard_gui.py`).

## Scope and limitations

- **Not high frequency.** Orders go to Kraken Futures over HTTP and websockets. There is no colocated infrastructure, no latency benchmark and no market-microstructure claim in this repository.
- **No verified track record.** Reports and execution logs generated by the system are research output, not audited performance.
- **Live capital.** The system has traded real money. That is a statement about intent, not about profitability.
- Account balances, positions and execution logs are excluded from version control; the local backup stays outside the repository.
